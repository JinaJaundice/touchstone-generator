# gen

## Overview

This directory is the synthetic data generator. It builds a seeded UK bank (accounts, a payment graph, ordinary life on a real calendar), plants labelled crime patterns in it and returns one `Dataset` with the transaction log, the truth flags and the pattern register. It also holds the bank builder model, the data dictionary, the Parquet writer and the worker that runs the generator off the main thread.

## Interface

- `generate.ts`: `generate(config, walletPool, progress?, poolAbout?)` returns a `Dataset`. Also `readWalletPool` and a re-export of `GENERATOR_VERSION`, `classOf`, `streamSeed`, `STREAMS` and `StreamTag`, which now live in `walletClass.ts` and `streams.ts` and are exported again here under the same names. It calls `scheduleLibrary` after `scheduleCrypto`, and `settleLibrary` after the planted patterns without a transaction are removed. It reports the stage "planting library patterns" and adds `library` to the summary only where a library pattern is switched on with a rate above 0.
- `streams.ts`: `mix32`, `tagHash`, `STREAMS`, `StreamTag` and `streamSeed(seed, period, tag)`, where a tag of the form `lib:` and a pattern id gives the stream of one library pattern. `walletClass.ts`: `classOf`, which maps the class of a screening tool onto the 8 wallet classes of the rail. Both are kept apart so that the planter of the pattern library can use them without importing `generate.ts`.
- `version.ts`: `GENERATOR_VERSION`, kept in its own file so a page can read it without loading the generator.
- `types.ts`: the data model (`GenConfig`, `Dataset`, `Account`, `Tx`, `AccountEvent`, `PatternInstance`, the typology and family types) and the label tables such as `TYPOLOGY_FAMILY`, `TYPOLOGY_LABEL` and `HIGH_RISK_COUNTRIES`. `PatternKey` is a built-in name or a key of the form `lib.<pattern id>.<end>`. `Party`, `CaseLeg`, `LibrarySetting`, `LibraryCase` and `LibraryRecord` hold the answer key and the settings of library patterns, and `Dataset.parties` and `Dataset.caseLegs` are empty, and `Dataset.library` and `DatasetSummary.library` are absent, where no library pattern is switched on. `patternLabel`, `patternShort` and `patternFamily` also answer for a library key, from `patterns/labels.json`.
- `config.ts`: `DEFAULT_CONFIG`, `PRESETS`, the typology defaults, `normaliseConfig`, `normaliseLibrary` (which keeps, fills and limits the entries of `library` and leaves the field out where none remain), `cashFactor` and `abroadShare`.
- `client.ts` and `worker.ts`: `runGenerator(config, onProgress?)`, `loadWalletPool()` and `loadWalletPoolFile()` (the wallets, the file's own account of its origin and whether the pool is generated) on the page side, and `TX_SLICE` with the message handler on the worker side. The worker also posts the rows of `caseLegs` and `parties` after the transactions, as messages `{ kind: "rows", table, rows }` of at most `TX_SLICE` rows, and its `done` message carries the 2 tables as empty arrays with their numbers of rows as `caseLegCount` and `partyCount`.
- `world.ts`, `population.ts`, `normal.ts`, `aml.ts`, `fraud.ts`, `crypto.ts`, `scheduler.ts`, `calendar.ts`, and `address.ts`: the `World` class, `buildAccounts`, `buildGraph`, `scheduleNormalModels`, `scheduleAml`, `scheduleFraud`, `scheduleCrypto`, `makeCalendar` and `makeSegwitAddress`. `address.ts` also holds `makeEthAddress`, `makeTronAddress` and `sha256`, written without a package. `World.schedule` returns whether it queued the leg, a `Scheduled` leg may hold `leg: { caseId, seq }`, and `World.emit` tells `onLibraryLeg` what happened to such a leg.
- `archetypes.ts`: the seven bank archetypes, the `DIALS`, `DIFFICULTY`, `estimate`, `stats`, and the share-link and saved-bank functions `encodeBank`, `decodeBank`, `loadSavedBanks` and `storeSavedBanks`.
- `calibrate.ts`: `calibrate`, `readFigures` and `figuresTemplate` (format `touchstone-figures/1`).
- `dictionary.ts`: the field specifications and `checkRecord`, which accepts a record that leaves out a field marked `optional`. `PARTY_FIELDS` and `CASE_LEG_FIELDS` specify the 2 tables of the answer key, `PATTERN_FIELDS` has the optional field `library`, and `LIBRARY_KEYS` lists the keys of the library patterns that a `typology` field also accepts. `message.ts`: `renderMessage` and `messageText`. `parquet.ts`: `txParquet` and `accountsParquet`. `csv.ts`: `txCsv`, `accountsCsv`, `caseLegsCsv`, `partiesCsv` and `csvValue`, the CSV files of the Make data page. `parquet.ts` also holds `CASE_LEG_COLUMNS`, `PARTY_COLUMNS`, `caseLegCell` and `partyCell`, which the 2 new CSV files use and which have no Parquet file in this release. `fingerprint.ts`: `fingerprint(ds)`.
- `caseView.ts`: the data of a drawn case, with no React and no DOM. `listCases(ds)` lists the planted cases, `caseView(ds, caseId)` turns one into parties and legs, `flowColumns` gives the columns of its drawing (at most `DRAWN_COLUMNS`, which is 8, where the ledger is drawn), `caseSteps`, `stepTitle`, `pickCase`, `patternCases` and `patternSteps(ds, key, own?)` give its steps and the steps of a pattern in the order of the largest case, `partyName` gives the full name of a party for a row, and `ROLE_WORD` names the roles.
- Data files: `sources.json` holds every figure the generator is calibrated to, with its register identifier. `patterns/references.json` holds the identifier and title of each source that a file of this directory cites, and `scripts/write-references.ts` writes it in the working repository. Each title is the text of the row of that source in `public-copy/docs/SOURCES.md`, up to its first full stop.
- `patterns/`: the pattern library, with crime patterns that are held as files. It holds `types.ts` (the types of the 2 file formats, the plan and the priced case, and the lists of allowed values), `validate.ts` (`validatePart`, `validatePattern`), `expand.ts` (`drawPlan`, `price`, `expandCase`, `typicalCase`), `index.ts` (`PARTS`, `PATTERNS`, `partOf`, `patternOf`), `labels.ts` and `labels.json` (the names of each pattern and its keys), `plant.ts` (`scheduleLibrary`, `settleLibrary`, `patternsOn`, `needSentence`, `LIBRARY_ROW_CAP` and `setRowCap`), `version.ts` (`LIBRARY_VERSION`), the 6 part files under `parts/` and the 2 pattern files under `library/`. A data set uses it only where a user switches a library pattern on. The format of a file and the rules of the planter are in `docs/PATTERN_FORMAT.md`. See [patterns/README.md](./patterns/README.md).
- The shared helpers `rng.ts` and `stats.ts` are in `web/src/lib/`. The screening list `lib/lists/ofac.json` has no README because it holds data only.

## Invariants

- The generator must not import code that tests or scores its data, and such code may import only from `gen/types.ts` in this directory. In the working repository `scripts/lib/wall.mjs` enforces both limits and `node scripts/design-check.mjs` exits 1 on a breach. That script is not part of `npm run build`.
- The truth (pattern, family, leg role) travels on the record for marking and for the files, and no rule may read it (header of `types.ts`).
- Every random draw comes from a seeded stream. `streamSeed` mixes the seed, the period and one of the `STREAMS` (`life`, `aml`, `fraud`, `crypto`, `days`), so a change to one family's dials changes only that family's draws.
- A seed gives the same bank only under the same release. `GENERATOR_VERSION` must be bumped whenever the output of a seed changes (comment in `generate.ts`).
- Period 1 starts on the date in `sources.json` (`calendar.day0`), and period n starts `(n - 1) * days` later (`periodStart` in `calendar.ts`).
- The worker sends transactions in slices of `TX_SLICE` (200,000) because a single message of 2.4 million records fails to clone, and `runGenerator` rejects when the count received differs from the count sent, for the transactions and for each of the 2 tables of the library cases. `estimate` in `archetypes.ts` adds, for each library pattern that is on, its number of cases multiplied by the number of ends that the bank sees, and it reads the ids from `patterns/labels.json` so that it imports neither `patterns/index.ts` nor `patterns/plant.ts`.
- The files under `patterns/` import `types.ts` and `dictionary.ts` of this directory and `../rng`, and the expander `patterns/expand.ts` imports `patterns/types.ts` and `../../rng` only. The planter `patterns/plant.ts` also imports `../address`, `../streams`, `../walletClass`, `../sources.json`, `../../rng` and the types of `../world` and `../types`, and it imports no file under `rules/`. It keeps its working state for a world in a map of its own, and it writes only `parties`, `caseLegs` and `library` of the world. A library pattern is off unless a user switches it on, so `GENERATOR_VERSION` does not change when a library file is added, and `LIBRARY_VERSION` changes when a file of the library changes.
- Every record must satisfy the specifications in `dictionary.ts`, which `scripts/qa-gen.ts` checks and `scripts/write-dictionary.ts` turns into `docs/DATA_DICTIONARY.md`.
- Counterparty wallets come from the wallet pool file `public/wallet_pool.json`, which states its own origin, and a customer's own wallet is a made segwit address with a valid checksum (`address.ts`).

## Side Effects

- `client.ts` fetches `./wallet_pool.json` once and starts a module worker from `./worker.ts`. A failed fetch resolves to an empty pool.
- `archetypes.ts` reads and writes `localStorage` under `touchstone-banks-v1`, keeps at most 12 banks and ignores storage errors.
- `worker.ts` posts progress, transaction slices, completion and error messages and reads `performance.now()`.
- `calendar.ts` reads `Date` for calendar arithmetic only.
- The generator code is otherwise deterministic for a given configuration and release.

## Verification

- `scripts/qa-gen.ts` runs in the working repository only, because it imports files that the public copy does not hold.

- Run in `web/`: `npx esbuild scripts/smoke-gen.ts --bundle --platform=node --format=esm --outfile=.tmp/smoke.mjs && node .tmp/smoke.mjs`
- Run in `web/`: `npm run build`, which type checks the directory.
